4.9.4  训练收敛性分析
====================================================================

为验证消融实验中各配置的训练充分性与公平性，本节对五组具有代表性的训练配置
进行了损失曲线的对比跟踪，分别记录了基线 LINEA-L（100 轮）、+MSLEP+SAI（130 轮）、
+MSLEP+SAI+EGAB（130 轮，独立训练，无 HASH）、+HASH 标准损失（v1，130 轮）以及
完整模型+排序损失（v2，130 轮）在整个训练过程中的回归损失（line loss）变化趋势。
图 X.Y 给出了五组配置的训练回归损失曲线，表 X.Y 进一步汇总了测试集上的收敛统计。

从图 X.Y 的走势来看，五条曲线展现出三个清晰可辨的层级。第一层级为基线
LINEA-L、+MSLEP+SAI 与 +MSLEP+SAI+EGAB，三者的训练回归损失在收敛后处于同一
量级，彼此差距有限。其中基线在约第 80 轮即进入平台区，100 轮的训练预算留有充足的
安全余量；+MSLEP+SAI 在约第 100 轮后趋于平稳；+MSLEP+SAI+EGAB 的回归损失略低
于前两者，反映了 EGAB 模块对注意力权重的熵偏置修正带来的正向增益，但在缺少 HASH
评分头的条件下该增益幅度有限。测试集上的定量统计（表 X.Y）与此一致：三者的最低
测试损失分别为 0.45、0.45 与 0.41，差异不超过 10%，说明仅凭解码器 logit 的标准 focal
分类损失，损失下界大约维持在 0.40 至 0.45 的区间。

第二层级为引入 HASH 评分头后的两组配置，二者的回归损失曲线在训练中后期均出
现明显的台阶式下降，与第一层级之间形成清晰的间隔带。HASH 的引入从根本上改变了
损失景观的形态：通过对每条候选线段执行基于多模态特征采样的独立置信度回归，HASH
为优化器提供了更加直接的梯度路径，使得模型能够在训练后期突破第一层级的损失下界。
从表 X.Y 来看，+HASH 标准损失（v1）在第 114 轮收敛至最低测试损失 0.11，较第一层级
的 0.41 下降了约 73%；完整模型+排序损失（v2）在第 109 轮收敛至 0.19。

值得注意的是，无论在图 X.Y 的回归损失曲线还是在表 X.Y 的测试损失中，v1（标准
损失）的最终损失均低于 v2（排序损失）。这一看似"反常"的现象恰好与第 4.9.6 节排序
质量分析的结论互为印证——排序损失在损失函数中引入了额外的成对 margin 约束项，该
约束项在迫使置信度输出与几何质量建立单调对应关系的同时，不可避免地增大了优化空间
中的约束密度，导致总体损失值略有抬升。然而，正如 4.9.6 节所揭示的，v1 虽然取得了
更低的损失数值，但其 EPE 损失比高达 1.52——模型"看得见却选不中"，实际检测精度
反而不如 v2。这表明训练损失的绝对值并非衡量最终检测精度的充分指标，排序损失通过
牺牲少量的损失数值来换取排序质量的大幅改善，在工程意义上是更优的训练策略。

├─────────────────────────────────┼──────┼──────────┼──────────┼──────────┤

上述结果从训练动态的角度提供了两层佐证。其一，消融表中前三组配置（基线、
+MSLEP+SAI、+MSLEP+SAI+EGAB）均在充分收敛后结束训练，性能差距源于模块本身的
特征增益而非训练不充分。其二，HASH 评分头是触发损失台阶式下降的核心架构变量，
而排序损失则在 HASH 之上进一步保证了排序质量与实际检测精度的一致性。

模块对模型体积与推理速度的影响，本节依次统计了从基线到完整模型的五级累进配置
在参数量、推理帧率（FPS）和单帧延迟方面的变化，结果列于表 X.Y。测试环境为
NVIDIA RTX 4090D GPU，输入分辨率 640×640，batch size 为 1，数据类型为 FP32，
每次测量包含 50 次前向推理取均值，以消除 GPU 预热与缓存波动的影响。

从参数量角度观察，熵先验注入通路（MSLEP+SAI+EGAB）三个模块合计仅新增
0.42M 参数，占基线参数量的 1.64%。其中 MSLEP 贡献了 0.37M，主要来源于将 3 通道
熵图映射至编码器特征维度的投影卷积与多尺度融合层；SAI 的参数增量仅 0.02M，因其
核心操作为逐通道的 sigmoid 加权，可学习参数极少；EGAB 以残差偏置的形式作用于解
码器的注意力输出，参数量 0.03M，在模型总量中几乎可忽略。HASH（地平线感知评分
头）是参数增量最大的单一模块，新增 1.14M，这是由于 HASH 内部需要沿候选线段采样
多个特征点并经过多层感知机进行置信度回归，涉及较多的全连接参数。排序损失是纯训
练时组件，不引入任何推理参数。

图 X.Y 以堆叠柱状图与折线的组合形式，同时呈现了五级配置在模块参数构成与推
理帧率两个维度上的变化。堆叠柱状体的不同色段对应骨干网络、编码器、解码器以及各
增强模块的参数份额，折线标记叠加于右侧纵轴表示对应的推理帧率，二者共享横轴以便
直观对比。从参数构成来看，骨干网络 HGNetv2-B4 在每组配置中均占据最大份额
（13.51M，约 49.5%），编码器在接入 MSLEP 后由 5.74M 增至 6.12M，解码器保持
6.50M 不变；熵注入通路的三个模块以分散的薄色段出现在编码器与解码器之间，不改变
骨干网络结构，因此可作为即插即用的轻量化增强组件灵活集成到其他基于 Transformer
的检测框架中，而无需对主干架构进行大规模修改。从折线走势来看，前四组配置的堆叠
柱高增长极为平缓（25.74M → 26.16M），对应折线从 39.3 缓慢下降至 34.9 FPS，累计
速度衰减约 11.2%，主要来源于 MSLEP 中多窗口局部熵计算所引入的额外卷积开销。
第五组（Full）的柱高出现可见跳变（27.30M），对应折线骤降至 29.4 FPS，额外带来约
15.8% 的速度损失。HASH 的延迟贡献较大，原因在于其需要在推理阶段对每条候选线段
执行逐点特征采样与前向评分，这一操作难以完全并行化。尽管如此，完整模型 29.4 FPS
的推理帧率仍然满足海上目标检测与避碰决策通常所要求的 25 FPS 实时性门限，可直接
用于无人艇的在线部署场景。

综上，本文所提出的熵注入增强方案在参数开销与推理延迟两个维度上均处于可接受
范围。MSLEP+SAI+EGAB 仅以 1.64% 的参数增量和约 11% 的速度代价，换取了消融表
中所展示的显著精度提升；即便接入参数量最大的 HASH 模块后，整体模型仍能维持
29.4 FPS 的实时帧率。这一结果表明，本文的模块化设计在精度与效率之间取得了良好
的工程平衡。

4.9.6  候选排序质量分析
====================================================================

在基于检测范式的海天线估计框架中，模型通常会生成大量候选线段并依据置信度得分
选取得分最高者作为最终输出。当候选池中已经存在与真实海天线高度接近的优质线段，
但模型却因得分排序不当而选择了精度较差的候选时，便产生了"看得见却选不中"的
排序退化问题。为定量诊断这一现象并验证排序损失的必要性，本节设计了候选排序质量
分析实验，在 MU-SID 测试集（268 张图像）上对四组配置进行排序行为的系统性对比。

具体而言，对于每张图像，我们首先计算所有候选线段与标注海天线之间的端点
误差（Endpoint Error, EPE），将 EPE 最小的候选定义为"oracle 最优候选"，其 EPE
记为 EPE_oracle；随后按照模型置信度得分由高到低排序，将得分最高的候选定义为
"实际选中候选"，其 EPE 记为 EPE_selected。基于此，本文定义三项排序质量指标：
Rank@GT 为 oracle 最优候选在得分排序中的平均名次（值越接近 1 表示排序越准确）；
Top-K 命中率为 oracle 最优候选落入得分前 K 名的图像占比；EPE 损失比
（EPE_selected / EPE_oracle）衡量因排序偏差而产生的精度折损，理想值为 1.00，偏离越
大说明排序浪费的精度越多。

四组实验的设计如下：基线 LINEA-L 使用独立训练的基线权重，以解码器 logit 作为
评分依据；+MSLEP+SAI+EGAB（独立训练）使用不含 HASH 评分头的独立训练权重，同
样以解码器 logit 作为评分依据；+HASH（标准损失）使用包含 HASH 评分头但仅以标准
focal 分类损失训练的 v1 权重；Full（+排序损失）使用以排序损失训练的 v2 权重并启用
HASH 评分头。结果列于表 X.Y。

实验结果揭示了三个层面的关键发现。

第一，解码器 logit 在不受 HASH 干扰的条件下具有良好的自然排序能力。基线
LINEA-L 的 EPE 损失比为 1.04，+MSLEP+SAI+EGAB（独立训练）的损失比进一步降至
1.02，表明解码器自身的分类 logit 已能将几何精度最优的候选排列在置信度排名的前列。
+MSLEP+SAI+EGAB 配置相较基线在 EPE_oracle 上从 5.18 降至 3.51 像素，说明熵注入
模块确实提升了候选线段的几何质量；而 EPE_selected（3.59 像素）与 EPE_oracle 之间
仅有 0.08 像素的差距（损失比 1.02），说明解码器 logit 的排序准确度足以将这一精度增
益近乎无损地传递至最终输出。

第二，HASH 评分头在标准 focal 分类损失下反而引发了严重的排序退化。+HASH
（标准损失）配置的 EPE_oracle 仅为 1.31 像素——这是四组配置中最低的，表明 HASH
结构本身在特征提取与候选生成层面带来了显著增益。然而，EPE_selected 却退化至
1.99 像素，EPE 损失比高达 1.52，意味着约 52% 的潜在几何精度因排序偏差而被浪费。
相比之下，不含 HASH 的 +MSLEP+SAI+EGAB（独立训练）配置虽然 EPE_oracle 较高
（3.51 像素），但损失比仅 1.02，排序质量远优于前者。这一对比揭示了排序退化的根本
机制：HASH 评分头接管了候选选择的决策权，但标准 focal 分类损失仅优化正负样本的
二元区分，不对正样本之间的相对几何质量施加序关系约束，导致 HASH 的置信度输出与
候选的 EPE 之间缺乏单调对应关系。解码器 logit 之所以能保持较好的排序，是因为其
分类得分与注意力权重天然耦合，隐含了对候选质量的粗略排序信号；而 HASH 独立于
解码器进行评分，一旦缺少显式的排序监督，便丧失了这一隐含的质量先验。

第三，排序损失精准修复了上述退化。完整模型 Full（+排序损失）将 EPE 损失比从
1.52 降至 1.02，Rank@GT 从 6.18 陡降至 1.01，Top-1 命中率提升至 99.25%，Top-5 与
Top-10 均达到 100.00%。排序损失通过对正样本之间施加成对 margin 约束，在训练阶段
显式要求"EPE 更低的候选必须获得更高的置信度得分"，从而使 HASH 的输出与候选
线段的几何精度建立起近似单调的对应关系。完整模型的损失比（1.02）与不含 HASH 的
+MSLEP+SAI+EGAB 配置完全一致，说明排序损失使 HASH 评分头恢复到了与解码器
logit 相当的排序精度水平，同时保留了 HASH 在 EPE_oracle 层面所带来的特征增益。

综合以上三层分析，可以清晰地勾勒出排序损失在本文框架中的角色定位：它既不是
独立提升检测精度的功能模块，也不是可选的辅助手段，而是 HASH 评分头正常工作的
必要训练条件。缺少排序约束时，HASH 仅具备二元分类能力，反而劣于解码器 logit 的
天然排序；施加排序约束后，HASH 才真正实现了对候选几何质量的精细区分，将"看得
见"与"选得中"统一起来。

为更直观地呈现上述分析，图 X.Y 以柱状图形式对比了四组配置的 EPE_oracle 与
EPE_selected，橙色填充区域对应损失比中被浪费的精度空间。此外，图 X.Y 展示了各
配置在所有测试样本上的 Rank@GT 分布箱线图，可以观察到 Full（+排序损失）的名次
分布高度集中于 1，而 +HASH（标准损失）的名次分布向右侧明显拖尾，与其 1.52 的
损失比形成了视觉上的对应。
