4.9.4  训练收敛性分析
====================================================================

为验证消融实验中各配置的训练充分性与公平性，本节对三组具有代表性的训练配置
进行了训练—测试损失曲线的对比跟踪，分别记录了基线 LINEA-L（100 轮）、+MSLEP+SAI
（130 轮）以及 +MSLEP+SAI+EGAB（130 轮）在整个训练过程中的测试损失变化，收敛
信息汇总于表 X.Y 与图 X.Y。

从收敛趋势来看（图 X.Y），基线 LINEA-L 的测试损失在第 82 轮附近到达极值
0.45 后趋于平稳，至第 100 轮结束时测试损失为 0.48，处于轻微回升但波动幅度不超过
0.03 的水平，表明 100 轮训练已经充分越过收敛拐点，后续继续训练不会带来显著的性能
增益。+MSLEP+SAI 配置因引入了额外的多尺度熵先验提取与空间自适应注入模块，模型
容量有所增加，收敛速度略慢于基线。该配置在第 102 轮到达最低测试损失 0.45，之后
基本保持稳定，至 130 轮结束时损失为 0.46。与基线相比，二者的最终损失水平十分接近，
这表明模块的接入虽然增加了参数量，但并未显著改变整体优化景观的形态。

+MSLEP+SAI+EGAB 配置的训练曲线表现出与前两组具有本质差异的特征。该配置在
引入熵引导注意力偏置（EGAB）后，测试损失在前 80 轮内维持了与 +MSLEP+SAI 相似
的下降速率；然而随着训练进入第 80 至 110 轮阶段，损失曲线出现了明显的"二次下探"，
在第 109 轮达到最低测试损失 0.19，相较于前两组配置的 0.45 水平实现了约 57% 的降幅。
这一现象说明 EGAB 不仅仅是一个附加的微调模块，而是从根本上改变了模型的特征表达
能力——通过将熵先验直接作用于变换器解码器的注意力权重，EGAB 使得解码器能够在
训练后期学习到更加精确的空间聚焦模式，从而实现了损失的质变性降低。值得注意的是，
该配置在第 109 轮到达极值后仍保持在 0.25 的较低水平，未出现过拟合迹象，表明 EGAB
的注意力调制机制具有良好的正则化效应。

收敛后的平稳区间。因此，消融表中不同配置之间的性能差距主要源于模块本身带来的
特征增益，而非训练不充分或学习率调度差异所致。此外，EGAB 引起的损失质变进一步

特征拼接的浅层注入（MSLEP+SAI）已经逼近了损失下界，只有将熵信号引入注意力计
算的深层语义通路，才能突破该性能瓶颈。

4.9.5  模型计算开销分析
====================================================================

实时性是海天线检测系统面向无人水面艇工程部署的刚性约束。为定量评估各增强
模块对模型体积与推理速度的影响，本节依次统计了从基线到完整模型的五级累进配置
在参数量、推理帧率（FPS）和单帧延迟方面的变化，结果列于表 X.Y。测试环境为
NVIDIA RTX 4090D GPU，输入分辨率 640×640，batch size 为 1，数据类型为 FP32，
每次测量包含 50 次前向推理取均值，以消除 GPU 预热与缓存波动的影响。

表 X.Y  各配置模型计算开销统计
┌─────────────────────┬──────────┬─────────┬─────────┬──────┬────────┬──────────┐
│ 实验配置             │ 总参数量 │ 增量    │ 增量占比│ FPS  │ 延迟   │ 速度比   │
│                     │ （M）    │ （M）   │ （%）   │      │（ms）  │          │
├─────────────────────┼──────────┼─────────┼─────────┼──────┼────────┼──────────┤
│ Baseline LINEA-L    │  25.74   │  —      │  —      │ 37.9 │  26.4  │  1.000   │
│ +MSLEP              │  26.11   │ +0.37   │ +1.44   │ 35.2 │  28.4  │  0.929   │
│ +MSLEP+SAI          │  26.13   │ +0.39   │ +1.51   │ 35.2 │  28.4  │  0.929   │
│ +MSLEP+SAI+EGAB     │  26.16   │ +0.42   │ +1.64   │ 35.0 │  28.6  │  0.923   │

└─────────────────────┴──────────┴─────────┴─────────┴──────┴────────┴──────────┘

从参数量角度观察，熵先验注入通路（MSLEP+SAI+EGAB）三个模块合计仅新增
0.42M 参数，占基线参数量的 1.64%。其中 MSLEP 贡献了 0.37M，主要来源于将 3 通道
熵图映射至编码器特征维度的投影卷积与多尺度融合层；SAI 的参数增量仅 0.02M，因其
核心操作为逐通道的 sigmoid 加权，可学习参数极少；EGAB 以残差偏置的形式作用于解
码器的注意力输出，参数量 0.03M，在模型总量中几乎可忽略。HASH（地平线感知评分
头）是参数增量最大的单一模块，新增 1.14M，这是由于 HASH 内部需要沿候选线段采样
多个特征点并经过多层感知机进行置信度回归，涉及较多的全连接参数。排序损失是纯训
练时组件，不引入任何推理参数。

从推理速度角度观察，基线 LINEA-L 在 RTX 4090D 上达到 37.9 FPS。逐步接入
MSLEP、SAI 与 EGAB 后，帧率从 37.9 平缓下降至 35.0 FPS，累计速度衰减约 7.7%；
考虑到三个模块合计参数增量不足 0.5M，该衰减幅度符合预期，主要来源于 MSLEP 中
多窗口局部熵计算所引入的额外卷积开销。接入 HASH 后帧率进一步降至 29.4 FPS，额
外带来约 16.0% 的速度损失。HASH 的延迟贡献较大，原因在于其需要在推理阶段对每
条候选线段执行逐点特征采样与前向评分，这一操作难以完全并行化。尽管如此，完整
模型 29.4 FPS 的推理帧率仍然满足海上目标检测与避碰决策通常所要求的 25 FPS 实时
性门限，可直接用于无人艇的在线部署场景。

从模块粒度分解来看（图 X.Y），骨干网络 HGNetv2-B4 占据整体参数的最大份额
（13.51M，约 49.5%），编码器在接入 MSLEP 后由 5.74M 增至 6.12M，解码器保持
6.50M 不变。熵注入通路的三个模块分散在编码器与解码器之间，不改变骨干网络结构，
因此可作为即插即用的轻量化增强组件灵活集成到其他基于 Transformer 的检测框架中，
而无需对主干架构进行大规模修改。

综上，本文所提出的熵注入增强方案在参数开销与推理延迟两个维度上均处于可接受
范围。MSLEP+SAI+EGAB 仅以 1.64% 的参数增量和 7.7% 的速度代价，换取了消融表
中所展示的显著精度提升；即便接入参数量最大的 HASH 模块后，整体模型仍能维持
29.4 FPS 的实时帧率。这一结果表明，本文的模块化设计在精度与效率之间取得了良好
的工程平衡。

4.9.6  候选排序质量分析
====================================================================

在基于检测范式的海天线估计框架中，模型通常会生成大量候选线段并依据置信度得分
选取得分最高者作为最终输出。当候选池中已经存在与真实海天线高度接近的优质线段，
但模型却因得分排序不当而选择了精度较差的候选时，便产生了"看得见却选不中"的
排序退化问题。为定量诊断这一现象并验证排序损失的必要性，本节设计了候选排序质量
分析实验，在 MU-SID 测试集（268 张图像）上对四组配置进行排序行为的系统性对比。

具体而言，对于每张图像，我们首先计算所有候选线段与标注海天线之间的端点
误差（Endpoint Error, EPE），将 EPE 最小的候选定义为"oracle 最优候选"，其 EPE
记为 EPE_oracle；随后按照模型置信度得分由高到低排序，将得分最高的候选定义为
"实际选中候选"，其 EPE 记为 EPE_selected。基于此，本文定义三项排序质量指标：
Rank@GT 为 oracle 最优候选在得分排序中的平均名次（值越接近 1 表示排序越准确）；
Top-K 命中率为 oracle 最优候选落入得分前 K 名的图像占比；EPE 损失比
（EPE_selected / EPE_oracle）衡量因排序偏差而产生的精度折损，理想值为 1.00，偏离越
大说明排序浪费的精度越多。

四组实验的设计思路如下：基线 LINEA-L 使用独立训练的基线权重，以解码器 logit
作为评分依据；"无 HASH（v1 权重）"与"+HASH（标准损失）"均使用以标准 focal
分类损失训练的 v1 权重，前者在推理时关闭 HASH 评分头从而回退至解码器 logit 评分，
后者启用 HASH 评分头；Full（+排序损失）使用以排序损失训练的 v2 权重并启用 HASH
评分头。结果列于表 X.Y。

表 X.Y  候选排序质量分析
┌──────────────────────┬────────┬────────┬────────┬────────┬──────────┬──────────────┬──────────┐
│ 实验配置              │Rank@GT │ Top-1  │ Top-5  │Top-10  │EPE_oracle│EPE_selected  │ 损失比   │
│                      │        │ （%）  │ （%）  │ （%）  │ （px）   │ （px）       │          │
├──────────────────────┼────────┼────────┼────────┼────────┼──────────┼──────────────┼──────────┤
│ Baseline LINEA-L     │  6.78  │ 97.39  │ 97.39  │ 97.39  │   5.18   │    5.41      │  1.04    │
│ 无 HASH（v1 权重）   │  6.18  │ 97.39  │ 98.13  │ 98.51  │   1.31   │    1.99      │  1.52    │
│ +HASH（标准损失）    │  6.18  │ 97.39  │ 98.13  │ 98.51  │   1.31   │    1.99      │  1.52    │
│ Full（+排序损失）    │  1.01  │ 99.25  │ 100.00 │ 100.00 │   1.61   │    1.64      │  1.02    │
└──────────────────────┴────────┴────────┴────────┴────────┴──────────┴──────────────┴──────────┘

表 X.Y 中最值得关注的是中间两组——"无 HASH（v1 权重）"与"+HASH（标准
损失）"。二者使用以标准 focal 分类损失训练的同一份 v1 权重，区别仅在于推理时是否
启用 HASH 评分头：前者关闭 HASH、由解码器 logit 决定候选排序，后者启用 HASH。
然而两组的排序指标几乎完全一致——Rank@GT 均为 6.18，Top-K 命中率相同，EPE 损
失比均为 1.52。这一结果否定了"排序退化源于 HASH 评分头接管了选择权"的直觉解释，
真正的瓶颈在于训练目标本身：标准 focal 分类损失仅优化正负样本的二元区分，不对正
样本之间的相对几何质量施加序关系约束，因而无论由解码器 logit 还是 HASH 执行排序，
模型都无法在多条高置信度候选之间识别出几何精度最优者。

图 X.Y 以柱状图形式直观呈现了这一排序偏差的后果。四组配置的 EPE_oracle（绿色）
与 EPE_selected（红色）并排展示，二者之间的差值即为因排序偏差而被浪费的精度空间。
基线 LINEA-L 的 EPE_oracle 为 5.18 像素，EPE_selected 为 5.41 像素，二者差距有限
（损失比 1.04），因为候选池中本就缺少高精度选项，排序偏差的绝对代价不大。而中间
两组的 EPE_oracle 已降至 1.31 像素，说明 MSLEP、SAI、EGAB 等模块确实将候选质量
提升至了亚像素级别；但 EPE_selected 却退化至 1.99 像素，约 52% 的几何精度被白白
浪费——候选池中明明有更好的线段，模型却没有选中。

图 X.Y 的 Rank@GT 箱线图从分布层面进一步印证了上述发现。"无 HASH（v1 权
重）"与"+HASH（标准损失）"两组的箱体和离群点分布形态高度重合，再次确认排序
退化与评分架构无关。而完整模型 Full（+排序损失）的名次分布高度集中于 1，几乎不
存在离群样本，与其他三组形成鲜明反差。从数值来看，Full 将 Rank@GT 从 6.18 降至
1.01，EPE 损失比从 1.52 降至 1.02，Top-1 命中率提升至 99.25%，Top-5 和 Top-10
均达到 100.00%。排序损失通过对正样本之间施加成对 margin 约束，在训练阶段显式要
求几何精度更高的候选必须获得更高的置信度得分，从而使 HASH 的输出与候选线段的
EPE 建立起近似单调的对应关系。

上述分析揭示了排序损失在本文框架中的角色定位：它既不是独立提升检测精度的功能
模块，也不是可选的辅助手段，而是 HASH 评分头正常工作的必要训练条件。缺少排序
约束时，无论使用解码器 logit 还是 HASH 评分头，模型都只具备二元分类能力；施加排
序约束后，HASH 才真正实现了对候选几何质量的精细区分，将候选池中的潜在精度近乎
无损地传递至最终输出。
